02 · Anticipated questions

What Dr. Ihab Ramadan is likely to ask

Each card below carries the question, the canonical answer, and the team member who owns it. Practice the answers out loud — the doctor reads your confidence as much as your content.

Q1Mahmoud · Most expected
Why didn't you use a real backend or a real database?
The assignment asked us to mock storage in-memory behind the Repository pattern. The architecture is built so that swapping to PostgreSQL, MongoDB, or any other store is a one-line change in app.module.ts. We invested time in patterns and SOLID rather than DB setup. The PostgreSQL adapter is the first item in our Enhancement Backlog.
Q2Ali · Repository
What is the Repository pattern and why did you use it?
An abstraction over data persistence. It hides storage details behind an interface so business logic doesn't depend on RAM, SQL, or a cloud service. Required by the assignment, satisfies DIP, and makes future migrations cheap.
Q3Ali · Strategy
Why three Strategy implementations?
To prove the pattern, not because the system needs three. UUID for global uniqueness, Short for human-friendliness, Numeric for fast manual entry. Adding a fourth (e.g. ExpiringCode) costs zero edits to TicketService.
Q4Amr · SOLID — DIP
How do you prove Dependency Inversion?
Two ways. (1) Run grep -r 'InMemory' src/service/ — returns nothing. (2) Every service test injects a mock repository through Jest — only possible if the service depends on the interface, not a concrete class.
Q5Amr · SOLID — LSP
Show LSP in your code.
Open the class diagram. ConcertEvent, ConferenceEvent, SportsEvent all extend Event. The repository stores them as Event; the service operates on them as Event. Each respects the constructor and decrementCapacity contract.
Q6Seif · Testing
What is your test coverage?
46 unit tests. Repository layer 100%, service layer ≥ 80%. Every service test mocks its repository — the act of mocking proves DIP is wired correctly.
Q7Ali · Tech Stack
Why NestJS instead of Express or Spring?
NestJS gives us first-class DI tokens, modular architecture, and Swagger generation out of the box. It maps the patterns we needed (Repository, Factory, Strategy) directly onto the framework. Spring would also work — NestJS is the JS-native equivalent.
Q8Ali · Patterns scope
Where is the Observer pattern?
De-scoped intentionally. The assignment requires 2–3 patterns; we delivered three deeply rather than four shallowly. Observer is the first architectural item in the Enhancement Backlog — natural fit for ticket lifecycle notifications.
Q9Mahmoud · Agile
How did you manage Agile in a student team?
Scrum with four 1-week sprints. Every sprint had a plan, daily standup, review, and retrospective documented in Notion. Every PR referenced a SET-T issue key. The Notion workspace doubles as a Jira-style backlog with Epics, Stories, Tasks, and saved views.
Q10Ali · TypeScript / DI
Why interfaces if TypeScript erases them at runtime?
NestJS solves this with provider tokens — we bind the symbol 'TICKET_REPOSITORY' to a concrete class in the module. The injection works at runtime even though the interface is compile-time only.
Q11Mahmoud · Retrospective
What would you do differently?
Two-hour architecture kickoff on Day 1; pair-programming rotation from Day 1; reserve the last day exclusively for demo polish. We logged each in our final retrospective.
Q12Amr · End-to-end flow
Walk through a single use case end-to-end.
UC-3 Generate Ticket. Admin POSTs to /events/:id/tickets. Controller validates DTO. TicketService calls EventFactory + ITicketCodeStrategy. Repository stores. 201 returned with the ticket URL. Three patterns visible in one HTTP call.
03 · Demo-day tips

Don't get caught off-guard

Before you walk in

Run the deck and the live system once, end-to-end, with a stopwatch.

  • Pre-seed three events on /admin so the dashboard isn't empty.
  • Pre-open four browser tabs: /admin · /tickets/[a-valid-id] · /api-docs · class diagram PNG.
  • Have the recorded demo MP4 ready in case localhost misbehaves.
  • Don't read from slides — slides are the backdrop, you are the speaker.
  • If you don't know an answer, say "great question — let me defer to [teammate]" and pass the mic. Looks confident, isn't fake.
